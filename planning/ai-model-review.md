# AI model review and adoption plan

Review date: October 17, 2026. Source baseline: fork commit `08dc510`, based on upstream `53618ff`. The complete [inventory](model-inventory.json) contains every registered application model ID and the local Ollama model digests. Model candidates below are recommendations for evaluation; they were not downloaded or benchmarked in this review.

## Current application inventory

The fork registers **75 unique ML model IDs**: 58 image/text search encoders, four face-model packs, and 13 OCR options. The server's search dimension table agrees with the 58 search IDs in the Python registry. These are supported choices, not evidence that all 75 weights are installed. The running Immich deployment and its downloaded model cache have not been inspected.

The code defaults are `ViT-B-32__openai` for search, `buffalo_l` for faces, and `PP-OCRv5_mobile` for OCR. Near-duplicate detection reuses image-search embeddings and has no separate default model. Exact-content checksums are not an AI model. Gemma is currently a local experiment outside Immich's native feature path.

Sources: [model registry](../machine-learning/immich_ml/models/constants.py), [search dimensions](../server/src/constants.ts), [configuration defaults](../server/src/dtos/config.dto.ts), [duplicate detection](../server/src/services/duplicate.service.ts), and [OCR settings](../web/src/routes/admin/system-settings/MachineLearningSettings.svelte).

Immich's published English retrieval benchmark reports 69.90 for default CLIP, 84.86 for base SigLIP 2, and 85.99 for SO400M SigLIP 2. Its measured CPU encoding times are 2.26, 5.81, and 56.57 ms respectively. These scores combine retrieval recalls on the documented datasets; they are not personal-library accuracy or full search-response times. Use them to choose candidates, not promise a speedup. [Immich benchmark](https://docs.immich.app/features/searching/).

Paddle's current PP-OCRv6 release offers three sizes and broader unified language support; tiny excludes Japanese from the small/medium language set. Its speed and quality claims come from Paddle's own evaluation, so repeat them on the fork's exports, previews, and hardware before switching defaults. [Paddle technical documentation](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv6/PP-OCRv6.en.md).

Google's current Gemma 4 family supports visual inputs and multiple deployment sizes. Published memory figures vary by format and runtime and do not establish that several models can coexist with Docker, the database, and the desktop. Measure total resident memory, context/cache growth, memory pressure, and cold-start behavior. [Gemma 4 overview](https://ai.google.dev/gemma/docs/core).

EmbeddingGemma 2 provides a 768-dimensional shared space and supports reduced dimensions. Its published deployment instructions require BF16 or FP32 rather than FP16; reduced vectors must be normalized and use the same dimension for query and corpus. Load only the required modality encoders. This is a model-specific contract, not a global precision rule for every model. [Model instructions](https://huggingface.co/google/embeddinggemma-2).

The InsightFace library license and the provided pretrained-weight terms differ. Upstream lists public pretrained models as restricted to non-commercial research, while Immich documents its own permission and limits on third-party redistribution/commercial use. Keep weight-license review as a distribution decision for this fork and evaluate a suitably licensed alternative if needed. [InsightFace model terms](https://github.com/deepinsight/insightface/blob/master/python-package/docs/model_zoo.md), [Immich acknowledgement](../machine-learning/README.md).

The candidate model metadata in the inventory records exact upstream revision IDs and advertised licenses for the checkpoints inspected. Those are source-repository revisions, not verified downloaded weight checksums. A release manifest must also pin the actual exported/quantized artifact and runtime compatibility.

The review compares current published candidates by task and integration cost; it does not rank every available model or identify one universal winner. Competitor user experiences can inform the product without becoming runtime dependencies. Do not assume that a competitor's private photo-service models are available as downloadable replacements.

## Recommended processing profiles

| Profile  | Initial proposal                                                                                                                                                     | Processing location                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Minimal  | Existing CLIP or a measured efficient SigLIP option; lower-cost face detector; language-appropriate OCR; captions optional.                                          | CPU-only host or constrained computer.                                    |
| Balanced | Base SigLIP 2; existing face default; evaluate PP-OCRv6_small; installed Gemma 3 4B baseline followed by an E2B/E4B evaluation. One background generation at a time. | This Mac or equivalent server; native generation runtime where useful.    |
| Quality  | SO400M SigLIP 2 or an evaluated EmbeddingGemma 2/Qwen retrieval index; evaluated OCR medium profile; larger Gemma for background enrichment; optional reranker.      | Stronger separate computer, with explicit routing and permitted fallback. |

These profiles are candidates, not new defaults. Each task can run locally or remotely. The model pair, preprocessing, revision, and index identity must remain compatible across worker failover. Keep the quality controls understandable in normal settings and expose individual models in Advanced.

## Evaluation and standards

Use one reproducible corpus across candidates: begin with 1,000 consented representative photos, approximately 200 annotated search requests, a face subset covering real household variation, a text-in-photos subset, and a small video subset. Expand to 10,000 and 100,000 assets for indexing and filter-performance testing. Separate development examples from held-out evaluation; keep each near-identical burst entirely within one partition to prevent leakage.

Measure Recall@20, nDCG@10, person-filter correctness, date/boolean-plan correctness, OCR character/word error rates, caption factuality, false face merges/splits, and near-duplicate false positives. Include different languages, low light, small faces, aging, documents, screenshots, pets as objects, mixed media, restrictive access scopes, and remote-worker failure. Do not evaluate identity accuracy through general image-search benchmarks.

Report warm and cold p50/p95 latency, initial-results latency, assets indexed per hour, peak resident RAM/VRAM, memory pressure, artifact size, and interrupted-job recovery. Measure local versus remote performance with upload bytes and network delay included. Pairwise trials should use the same prompts, previews, language mix, candidate set, and user permissions; compare ranking lists rather than blend incompatible raw similarity scores.

Apply the following engineering standards to every admitted model:

- Versioned input/output schemas and explicit modality/task declarations. JSON-schema-shaped output still needs semantic validation, especially for dates, identities, and exclusions.
- Model cards, exact license/weight terms, pinned revisions, artifact checksums, and documented preprocessing and normalization.
- Runtime-specific validation for ONNX, CoreML, CUDA/OpenVINO, or a native generative runtime. “Open weights” does not imply existing ONNX exports or identical API behavior.
- ACL-scoped retrieval, access rechecks before results are displayed, and propagation of deletion/permission changes to all derived records and caches.
- Side-by-side index migrations with rollback, separate namespaces for incompatible embeddings, and duplicate/face threshold recalibration.
- Per-task resource budgets, bounded queues, warm-model policy, and no automatic model upgrades behind mutable `latest` tags in production.

Keep supplier MTEB, MMEB, OCR, and Immich retrieval scores separate because their tasks and datasets differ. Adopt a model only when it wins the product's quality/cost gate. Recheck candidate releases before each major model update; newly released models do not bypass the same evaluation, migration, and local/remote compatibility checks.
